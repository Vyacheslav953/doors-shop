# Doors M

Сайт продажи межкомнатных дверей: каталог, конфигуратор с ориентировочной ценой, заявка на звонок менеджера.
Next.js 16 + Payload CMS 3 (админка `/admin`) + SQLite + Tailwind 4.

## Запуск

```bash
npm install
npm run seed   # админ, настройки и демо-каталог (можно запускать повторно)
npm run dev    # http://localhost:3000, админка: /admin
```

Логин и пароль админа берутся из `ADMIN_EMAIL` / `ADMIN_PASSWORD` в `.env` (для разработки `admin@doorsm.local` / `admin`).
**Перед выкладкой на сервер сменить пароль.**

## Где что

- `src/collections`: Doors, Colors, Leads, Media, Users
- `src/globals/SiteSettings.ts`: телефон, наценка, монтаж, зоны доставки
- `src/lib/pricing.ts`: расчёт цены (общий для браузера и сервера)
- `src/app/(frontend)/api/lead/route.ts`: приём заявок (валидация, антиспам, пересчёт цены на сервере)
- Telegram-уведомления: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`

## Куда попадает заявка

`/api/lead` при каждой заявке:
1. пишет её в базу (раздел «Заявки» в админке);
2. **всегда** дописывает строку в Excel, на лист текущего месяца («Сентябрь 2026», новый лист создаётся сам при первой заявке месяца; месяц по Москве) (путь задаётся в админке: Настройки сайта → «Путь к Excel-файлу с заявками»; если пусто, то `LEADS_EXCEL_PATH` из `.env`, по умолчанию `data/leads.xlsx`), в том числе когда база недоступна;
3. отправляет одно уведомление в Telegram со статусом сохранения.

Если базы нет, строка в Excel помечена «ТОЛЬКО В EXCEL», а конфигурация взята со страницы и отмечена как непроверенная.
Если основной файл открыт в Excel или повреждён, заявка сохраняется в отдельный `leads-<время>.xlsx` рядом.
Строки из Excel в базу автоматически не переносятся. Файл содержит персональные данные, `data/` в git не попадает.

Путь из админки дублируется в `data/excel-path.json`, чтобы Excel работал и при недоступной базе. Смена пути не переносит старые строки.

## Деплой на Render (демо)

1. На https://dashboard.render.com/ → **New → Blueprint** → выбрать этот репозиторий. Render найдёт `render.yaml` и сам создаст сервис.
2. Перед применением заполнить в форме `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (не обязательно, можно пропустить и добавить позже в Environment сервиса). `PAYLOAD_SECRET` Render сгенерирует сам.
3. Нажать **Apply**. Первая сборка занимает несколько минут.
4. Открыть выданный адрес вида `https://doors-shop-xxxx.onrender.com`, админка на `/admin`.

Образ собирается полностью внутри Docker (`Dockerfile`): `npm ci` → `next build` → в готовый образ добавляются
демо-база `deploy/doors.db` и фото `deploy/media` (без реальных заявок, пароль администратора задаётся отдельно, не `admin`).

**Важно про хранение данных.** Бесплатный план Render не даёт постоянный диск: при каждом новом деплое (`git push`)
файловая система контейнера пересоздаётся из образа, то есть из `deploy/doors.db`. Значит:
- заявки, оставленные посетителями во время демонстрации, переживут перезапуск/сон сервиса, но **пропадут при следующем деплое**;
- чтобы обновить демо-каталог на сайте, нужно пересобрать `deploy/doors.db` (см. ниже) и запушить.

Для сайта, который уже реально работает и принимает заявки, нужен постоянный диск (платный план Render + Disk,
смонтированный на `/app/data` и `/app/media`) или отдельная управляемая база вместо SQLite.

### Обновить демо-данные перед деплоем

```bash
Copy-Item doors.db deploy\doors.db -Force
Copy-Item media deploy\media -Recurse -Force
# сменить пароль администратора на не-«admin» в скопированной базе, например через payload run на deploy/doors.db
```

Затем закоммитить `deploy/doors.db` и `deploy/media` и запушить — Render передеплоит сайт автоматически.
